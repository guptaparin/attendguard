AttendGuard App Map

A take-home guide to how the app is put together: what happens when you tap a button, and where to start if you want to change something.

Snapshot of the code at the final-review commit on branch main. The code may drift from this map as the project changes.

The three pieces

  • The calculatorsrc/attendance.js
    Plain functions that turn held, attended, and the required % into a verdict. No UI, so it's easy to test.
  • The state + save slotsrc/useSubjects.js
    Holds every subject and the required %, and saves them to the browser's localStorage after each change.
  • The screensrc/App.jsx + src/components/
    React components that draw the header, summary, cards, and form.

One action, end to end: tapping Absent

Code route: 3 stops (reference)

This route wasn't toured live with the learner. Use it as a reference: open the project in your editor and search for each anchor.

  1. The button. src/components/SubjectCard.jsx, search btn-absent. The Absent button calls onMark(false), which App.jsx wires to mark(s.id, present).
    Show the code 
    <button className="btn btn-absent" onClick={() => onMark(false)}>✕ Absent</button>
  2. The update and the save. src/useSubjects.js, search mark: (id, present). It adds 1 to held (and to attended for Present), remembers the old counts in last for Undo, and the useEffect below writes everything to localStorage.
    Show the code 
    mark: (id, present) =>
  patch(id, (x) => ({
    ...x,
    held: x.held + 1,
    attended: x.attended + (present ? 1 : 0),
    last: { held: x.held, attended: x.attended, present },
  })),
  3. The math. src/attendance.js, search export function verdict. With held 41, attended 36, and 75%, skippable gives floor((3600 − 3075) / 75) = 7, so the card shows 7.
    Show the code 
    export function skippable(held, attended, required) {
  return Math.floor((100 * attended - required * held) / required);
}

A practice to reuse

Write the expected numbers down before writing the code. devpost/prd.md → The Verdict listed concrete cases (36/40 → skip 8, 25/40 → attend 20, 0/0 → no classes yet) before any code existed. Those became src/attendance.test.js, plus a brute-force simulation over every combination up to 60 classes. Because the formula was proven before the UI depended on it, no bug in the app could come from the math.

On your next project, put a few concrete input → output examples in the plan for the one part that must be right. Turn them into tests first, then build on top of them.
